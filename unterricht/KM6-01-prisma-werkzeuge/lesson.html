1. Ziel dieser Lesson

Am Ende hast du ein lauffähiges, migriertes Prisma-7-Projekt mit dem TypeScript-Client — und du kennst die Werkzeugkette: Schema schreiben, mit migrate versionieren, mit db pull eine Altdatenbank einlesen und mit Studio in die Daten schauen. Die CRUD-Abfragen kommen in der Folge-Lektion KM6-02.

2. Warum Node — und welcher Client?

Die Klasse arbeitet sonst mit Deno/TypeScript. Für Prisma 7 mit SQLite gilt: Deno ist nicht kompatibel (Prisma 7 hat die Rust-Engine entfernt und braucht einen nativen Driver Adapter). Deshalb: Node.js als Transportmittel, unser Anwendungscode bleibt TypeScript.

Und wir verwenden immer den TypeScript-Client, also den Generator prisma-client — nicht das alte prisma-client-js. Das alte erzeugt CommonJS und bricht unter ESM:

// ✗ alter Generator: CommonJS, unter ESM nicht als Named-Export nutzbar
import { PrismaClient } from "@prisma/client";

Der neue Generator schreibt echte TypeScript-Dateien in einen eigenen Ordner — und die importieren wir direkt.

3. Projekt aufsetzen

npm init -y
npm pkg set type=module          # ESM

# CLI + TypeScript-Runner
npm i -D prisma@7 tsx
# Client + SQLite-Adapter + .env
npm i @prisma/client@7 @prisma/adapter-better-sqlite3@7 dotenv

Bitte auf @7 pinnen: ein ungepinntes npm i prisma zieht sonst die Prisma-8-Vorabversion.

4. Die CLI-Konfiguration

Prisma 7 liest die Verbindungsdaten aus einer Config-Datei — nicht mehr aus Flags wie --schema/--url (die wurden entfernt). Die Datei heißt ab 7.10 prisma7.config.ts (der CLI findet auch prisma.config.ts):

// prisma7.config.ts
import "dotenv/config";
import { defineConfig, env } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: { path: "prisma/migrations" },
  datasource: { url: env("DATABASE_URL") },
});
# .env
DATABASE_URL="file:./dev.db"

5. Das Schema (Prisma Schema Language)

// prisma/schema.prisma
generator client {
  provider = "prisma-client"     // TypeScript-Client!
  output   = "../generated/prisma"
}

datasource db {
  provider = "sqlite"
}

model Sammlung {
  id     Int      @id @default(autoincrement())
  name   String   @unique
  medien Medium[]
}

model Medium {
  id         Int      @id @default(autoincrement())
  titel      String
  jahr       Int?
  sammlungId Int
  sammlung   Sammlung @relation(fields: [sammlungId], references: [id], onDelete: Cascade)
  tags       Tag[]    // n:m — Prisma legt die Zwischentabelle implizit an
}

model Tag {
  id     Int      @id @default(autoincrement())
  name   String   @unique
  medien Medium[]
}

Beziehungen stehen als Felder (medien, tags); daraus baut Prisma Fremdschlüssel und Zwischentabelle. ? heißt optional (NULL erlaubt).

6. Client erzeugen und verbinden

npx prisma generate
// src/db.ts — ein Driver Adapter ist Pflicht
import "dotenv/config";
import { PrismaBetterSqlite3 } from "@prisma/adapter-better-sqlite3";
import { PrismaClient } from "../generated/prisma/client.ts";

const url = process.env.DATABASE_URL ?? "file:./dev.db";
const adapter = new PrismaBetterSqlite3({ url });
export const prisma = new PrismaClient({ adapter });

tsx führt die .ts-Dateien direkt aus — kein Compile-Schritt.

7. Migrationen — „Schema-Git"

migrate dev vergleicht Schema und Datenbank (über eine Shadow-DB), erzeugt daraus eine SQL-Migration und wendet sie an:

npx prisma migrate dev --name init

Applying migration `20261005105826_init`
The following migration(s) have been created and applied:
prisma/migrations/ └─ 20261005105826_init/ └─ migration.sql
Your database is now in sync with your schema.

Die Migration ist echtes SQL, das du lesen und mit-committen kannst:

-- prisma/migrations/20261005105826_init/migration.sql (Auszug)
CREATE TABLE "Sammlung" (
    "id" INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
    "name" TEXT NOT NULL
);
CREATE TABLE "Medium" (
    "id" INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
    "titel" TEXT NOT NULL,
    "jahr" INTEGER,
    "sammlungId" INTEGER NOT NULL,
    CONSTRAINT "Medium_sammlungId_fkey" FOREIGN KEY ("sammlungId")
      REFERENCES "Sammlung" ("id") ON DELETE CASCADE
);
-- … plus Tag und die implizite n:m-Tabelle "_MediumToTag"
BefehlZweck
migrate dev --name xNeue Migration erzeugen + anwenden (nur Entwicklung)
migrate dev --create-onlyMigration nur erzeugen, nicht anwenden (zum Prüfen/Anpassen)
migrate statusZeigen, ob die DB zum Migrationsordner passt
migrate resetDB leeren, alle Migrationen neu anwenden
migrate deployVorhandene Migrationen anwenden (Staging/Produktion, keine neuen)
migrate diff / migrate resolveSQL-Diff zeigen / fehlgeschlagene Migration markieren
npx prisma migrate status
1 migration found in prisma/migrations
Database schema is up to date!

8. db push statt Migrationen (Prototyping)

Zum schnellen Ausprobieren schiebt db push den Schema-Stand direkt in die DB — ohne Migrationsdateien. Gut für Prototypen, schlecht fürs Team (keine Historie).

npx prisma db push
The database is already in sync with the Prisma schema.

9. db pull — Altdatenbank einlesen (Introspection)

Umgekehrter Weg: eine bestehende Datenbank ohne Prisma-Schema wird eingelesen und in Modelle übersetzt. Im Praxisprojekt liegt dafür altbestand/legacy.sql:

sqlite3 altbestand/legacy.db < altbestand/legacy.sql
DATABASE_URL="file:./altbestand/legacy.db" npx prisma db pull --print

model buecher {
  id    Int     @id @default(autoincrement())
  titel String
  autor String?
  jahr  Int?
}

Achtung: db pull überschreibt das Schema. Vorher committen; --print zeigt nur an, schreibt nichts.

10. Prisma Studio — in die Daten schauen

npx prisma studio --url file://./dev.db
Prisma Studio is running at: http://localhost:5555
Stolperstein Prisma 7.10 Mit der üblichen URL file:./dev.db bricht Studio ab: „not supported for the file:./dev.db protocol". Es zerlegt die URL am ://. Nimm für Studio die Doppel-Slash-Form file://./dev.db.

12. Typische Fehler

  • Falscher Generator: prisma-client-js erzeugt CommonJS → ESM-Import scheitert. Immer prisma-client.
  • Adapter vergessen: new PrismaClient() ohne { adapter } startet unter Prisma 7 nicht.
  • Ungepinntes Prisma: npm i prisma zieht die 8er-Vorabversion. Immer @7.
  • Keine .env: ohne DATABASE_URL findet die CLI die DB nicht.
  • Studio mit file:: Doppel-Slash file://./dev.db nötig.
