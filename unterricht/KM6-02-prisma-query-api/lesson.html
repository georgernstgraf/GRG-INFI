1. Ziel dieser Lesson

Nach KM6-01 steht das Fundament (Schema, Migration, TypeScript-Client). Jetzt holen wir die Daten: alle CRUD-Operationen über die Prisma Query API — create, find*, update, upsert, delete, plus Filter, select/include, Aggregate und $transaction.

Grundmuster — immer gleich:

const ergebnis = await prisma.<modell>.<methode>({ ... });

2. Der Aufbau

Wir arbeiten in src/crud.ts mit dem Client aus src/db.ts (Adapter + TypeScript-Client aus KM6-01) und der Domäne Mediensammlung.

import { prisma } from "./db.ts";

model Sammlung  → prisma.sammlung
model Medium    → prisma.medium
model Tag       → prisma.tag

Jedes Modell bekommt automatisch seine Methoden aus dem Schema (Typsicherheit inklusive).

3. CREATE — anlegen

// Ein Datensatz, verschachtelt mit Kindern (nested create):
await prisma.sammlung.create({
  data: {
    name: "Hörspiele",
    medien: { create: [ { titel: "Folge 1", jahr: 1979, bewertung: 5 } ] },
  },
  include: { medien: true },
});
// Viele auf einmal (gibt nur die Anzahl zurück):
await prisma.medium.createMany({
  data: [ { titel: "Folge 3", sammlungId: 9 }, { titel: "Folge 4", sammlungId: 9 } ],
});

Relationen werden beim Anlegen über connect (bestehend verknüpfen), create (neu anlegen) oder connectOrCreate (eins von beidem) gesetzt.

4. READ — lesen

MethodeLiefert
findUniquegenau einen Treffer über ein eindeutiges Feld — sonst null
findUniqueOrThrowwie oben, wirft aber statt null
findFirstden ersten Treffer einer Filtermenge
findManyeine Liste
await prisma.medium.findUnique({ where: { id: 3 } });
await prisma.sammlung.findUniqueOrThrow({ where: { name: "Jazz" } });
await prisma.medium.findMany({
  where: { bewertung: { gte: 4 }, tags: { some: { name: "Highlight" } } },
  orderBy: [{ bewertung: "desc" }, { titel: "asc" }],
  take: 5,
});

Filteroperatoren in where: equals, contains, startsWith, gt/gte/lt/lte, in, not, null; verknüpft mit AND, OR, NOT (Standard ist UND).

await prisma.medium.findMany({
  where: { OR: [ { jahr: { lt: 1960 } }, { titel: { contains: "Never" } } ] },
});

select vs. include — und Blättern

// select = Projektion: nur diese Felder (Relation als Teilprojektion)
await prisma.medium.findMany({
  select: { titel: true, jahr: true, sammlung: { select: { name: true } } },
});

// include = ganze Relationen mitladen
await prisma.sammlung.findMany({
  include: { medien: { include: { tags: true } } },
});
// Blättern: skip + take
await prisma.medium.findMany({ orderBy: { id: "asc" }, skip: 1, take: 2 });

select und include nie mischen — für alles, was nicht in select steht, gibt es keine Garantie.

5. UPDATE — ändern

// Teil-Update eines Datensatzes
await prisma.medium.update({ where: { id: 3 }, data: { jahr: 1960 } });

// Atomar hochzählen (statt lesen+schreiben): gegen Race-Conditions
await prisma.medium.update({ where: { id: 3 }, data: { bewertung: { increment: 1 } } });

// Mehrere auf einmal (gibt die Anzahl zurück)
await prisma.medium.updateMany({ where: { jahr: null }, data: { jahr: 2000 } });

upsert = Update oder Create in einem Aufruf (idempotent):

await prisma.tag.upsert({
  where: { name: "Neu" },
  update: {},                    // existiert -> nichts ändern
  create: { name: "Neu" },       // fehlt -> anlegen
});

6. DELETE — löschen

await prisma.medium.delete({ where: { id: 3 } });                 // genau einer
await prisma.medium.deleteMany({ where: { tags: { none: {} } } }); // alle ohne Tag

Das Löschverhalten von Beziehungen steuert das Schema (onDelete: Cascade löscht Kinder mit) — aus KM6-01.

7. Aggregate — zählen, rechnen, gruppieren

await prisma.medium.count();
await prisma.medium.aggregate({ _avg: { bewertung: true }, _max: { jahr: true }, _count: { _all: true } });
await prisma.medium.groupBy({ by: ["sammlungId"], _avg: { bewertung: true }, _count: { _all: true } });

8. Transaktionen — alles oder nichts

await prisma.$transaction(async (tx) => {
  const s = await tx.sammlung.create({ data: { name: "Transaktions-Test" } });
  await tx.medium.create({ data: { titel: "Atomar", sammlungId: s.id } });
  return tx.sammlung.findUnique({ where: { id: s.id }, include: { medien: true } });
});

Das ist die Prisma-Entsprechung zu BEGIN/COMMIT/ROLLBACK aus KM5: Schlägt ein Schritt fehl, wird alles zurückgerollt (ACID).

9. Fehler kennen

CodeBedeutung
P2025Datensatz nicht gefunden (update/delete/…OrThrow)
P2002Verletzung eines Unique-Constraints (z. B. doppelter Tag-Name)

Prisma-Client baut parametrisierte Queries — SQL-Injection ist strukturell ausgeschlossen (der Kontrast zu Raw SQL kommt in KM6 UE 5).

10. Der Fluchtweg: $queryRaw

// SQL ohne API-Entsprechung, typisiert zurückgegeben
const rows = await prisma.$queryRaw`
  SELECT s.name AS name, COUNT(m.id) AS anzahl
  FROM Sammlung s LEFT JOIN Medium m ON m.sammlungId = s.id
  GROUP BY s.id ORDER BY anzahl DESC`;
// Achtung: SQLite liefert COUNT als BigInt -> 4n statt 4

11. Typische Fehler

  • Nicht-eindeutiges where bei findUnique: dort sind nur @unique/@id-Felder erlaubt — sonst findFirst.
  • select + include gemischt: ergibt undefinierte Felder — nur eines von beiden.
  • Bewertung mit set statt increment: Race-Condition — atomar hochzählen.
  • BigInt unterschätzt: COUNT() aus $queryRaw ist 4n, nicht 4.
  • Fehlender where bei update/delete: die Einzel-Methoden verlangen immer eine eindeutige Angabe.
