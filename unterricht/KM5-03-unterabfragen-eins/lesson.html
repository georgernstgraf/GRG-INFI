1. Die Einstiegsfrage

„Welche Songs sind länger als der Durchschnitt?" — Das Problem: Den Durchschnitt kenne ich erst, wenn ich ihn berechnet habe. In Excel wären das zwei Schritte. In SQL geht das in einer Abfrage, indem man eine Abfrage in die andere schachtelt:

SELECT titel, dauer_sek
FROM song
WHERE dauer_sek > (SELECT AVG(dauer_sek) FROM song)
ORDER BY dauer_sek DESC;

Die eingeklammerte Abfrage liefert einen Wert (den Durchschnitt) — und der äußeren Abfrage ist es egal, woher er kommt. Das ist die Unterabfrage (Subquery).

2. Drei Formen, drei Orte

Unterabfragen liefern drei Arten von Ergebnissen — und passen an verschiedene Orte:

FormLiefertTypischer Ort
SkalarGenau einen WertWHERE dauer_sek > (SELECT AVG(…) …), auch in SELECT
ZeileGenau eine ZeileWHERE (a, b) = (SELECT …) (Tupelvergleich)
TabelleEine ErgebnismengeFROM (SELECT …) AS x — Alias in SQLite Pflicht

3. Skalar-Subqueries

Ein Skalar liefert genau einen Wert. Zwei Orte sind typisch:

(a) in WHERE — als Vergleichswert:

SELECT titel FROM song
WHERE dauer_sek > (SELECT AVG(dauer_sek) FROM song);

(b) in SELECT — als zusätzliche Vergleichsspalte pro Zeile:

SELECT titel,
       dauer_sek,
       (SELECT ROUND(AVG(dauer_sek), 1) FROM song) AS durchschnitt
FROM song
ORDER BY titel;

Der Durchschnitt ist in jeder Ergebniszeile derselbe Wert (212.5) — man kann die Dauer direkt mit ihm vergleichen.

4. Tabellen-Subqueries (in FROM)

Eine Tabellen-Subquery liefert eine ganze Ergebnismenge und wird in FROM wie eine Tabelle verwendet — deshalb heißt sie abgeleitete Tabelle. In SQLite ist der Alias Pflicht:

SELECT name, n
FROM (
  SELECT k.name AS name, COUNT(*) AS n
  FROM kuenstler k JOIN song s ON s.kuenstler_id = k.id
  GROUP BY k.id
) AS t
WHERE t.n >= 2
ORDER BY t.n DESC, t.name;

Erst wird innen gruppiert und gezählt, dann außen gefiltert. Das ist oft lesbarer, als alles in eine Abfrage mit HAVING zu quetschen — und subqueries dürfen beliebig tief verschachtelt werden.

5. Zeilen-Subqueries (Tupelvergleich)

Eine Zeilen-Subquery liefert genau eine Zeile. Man vergleicht sie mit einem Tupel in Klammern. Beispiel: „Auers längster Song" — der Künstler und seine Maximaldauer in einem Schritt:

SELECT titel, dauer_sek
FROM song
WHERE (kuenstler_id, dauer_sek) =
      (SELECT kuenstler_id, MAX(dauer_sek) FROM song WHERE kuenstler_id = 1);

Ohne Zeilen-Subquery bräuchte man zwei verschachtelte Skalar-Abfragen. Der Tupelvergleich macht die Absicht lesbar.

Subquery in FROMbraucht in SQLite fast immer einen Alias (AS x)
Subquery in WHEREskalar = ein Wert; Tupel = eine Zeile

7. Typische Fehler

  • Alias vergessen: FROM (SELECT …) ohne AS x bricht in SQLite.
  • Nicht-skalare Subquery in SELECT: Liefert die Subquery mehrere Zeilen, gibt es einen Fehler — dann JOIN oder IN nutzen.
  • Spaltenverwechslung: Außen auf eine Spalte zugreifen, die die Subquery nicht ausgibt.
  • Klammern vergessen: WHERE dauer_sek > SELECT AVG(…) — die Subquery muss in Klammern.
