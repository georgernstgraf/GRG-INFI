Unterabfragen I: Skalar, Zeile, Tabelle

KM5-Kern, Teil 1: schwierige Fragen in Stufen zerlegen — eine Abfrage in der anderen.

1. Das Ziel dieser Lesson

Du platzierst Unterabfragen gezielt in WHERE, FROM und SELECT. Dein Win: 3 Übungen auf der Musik-DB — je eine Skalar- und Tabellen-Subquery plus eine freie.

2. Wissen: drei Formen, drei Orte

FormLiefertTypischer Ort
SkalarGenau einen WertWHERE plays > (SELECT AVG(plays) …), auch in SELECT
ZeileGenau eine ZeileWHERE (a, b) = (SELECT …) (Tupelvergleich)
TabelleEine ErgebnismengeFROM (SELECT …) AS x — Alias in SQLite Pflicht
-- Skalar: über Durchschnitt?
SELECT title FROM track
WHERE plays > (SELECT AVG(plays) FROM track);

-- Tabelle: erst filtern, dann gruppieren
SELECT label, COUNT(*) AS n
FROM (SELECT * FROM artist WHERE active = 1) AS a
GROUP BY label;

Mehr Muster: Spickzettel · Begriffe: Glossar.

Regel: Subquery in SELECT muss skalar sein. Subquery in FROM braucht einen Alias. (Korreliert, EXISTS/IN + NULL-Falle folgen in UE 4.)

3. Üben: Quiz

1. Was liefert eine Skalar-Subquery?

2. Was braucht eine Subquery in FROM?

3. Wohin gehört der Durchschnittsvergleich?

4. Skill: dein Win

  1. Tracks über dem Durchschnitts-Playcount (Skalar-Subquery in WHERE).
  2. Anzahl aktiver Künstler pro Label über eine Tabellen-Subquery in FROM (mit Alias).
  3. Eine Abfrage mit Subquery in SELECT (z. B. Durchschnittswert als Vergleichsspalte pro Zeile).
HÜ (aus dem Semesterplan): genau diese 3 Übungen (Skalar-/Table-Subqueries) auf der Musik-DB.
