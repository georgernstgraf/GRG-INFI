Normalisierung 1NF–3NF

Lückenschluss aus KM3: eine „schlechte" Bestelltabelle schrittweise heilen — und jede Stufe begründen.

1. Das Ziel dieser Lesson

Du erkennst Anomalien (Einfüge-, Änderungs-, Löschfehler) als Schema-Fehler und zerlegst eine denormalisierte Tabelle bis 3NF. Dein Win: die HÜ-Tabelle mit Begründung pro Stufe.

2. Wissen: der Weg in drei Fragen

Ausgangslage (nicht normalisiert):

bestellung(id, kunde_name, kunde_ort, tracks, gesamt_preis)
StufeFrageWas tun?
1NFSteht in einer Zelle mehr als ein Wert? (tracks = "A,B,C")Pro Track eine Zeile: bestellposition(bestellung_id, track_id)
2NFHängt etwas nur von einem Schlüsselteil ab? (Track-Titel vom Track, nicht von der Bestellung)track(id, titel, preis) auslagern
3NFHängt etwas von einem Nichtschlüssel ab? (kunde_ort vom Kunden, nicht von der Bestellung)kunde(id, name, ort) auslagern

Begriffe: Glossar (Schema) · Checkliste: Spickzettel.

Denormalisierung (Ausblick): Für Lese-Performance legt man Tabellen später bewusst wieder zusammen — erst nach Messung, nie aus Bequemlichkeit.

3. Üben: Quiz

1. Was verletzt tracks = "A,B,C" in einer Zelle?

2. Was ist eine Anomalie?

3. Wann ist Denormalisierung richtig?

4. Skill: dein Win

  1. Zeige je eine konkrete Anomalie (Einfügen, Ändern, Löschen) an der Ausgangstabelle.
  2. Normalisiere bis 3NF: notiere die neuen Tabellen mit Schlüsseln (FK markieren).
  3. Begründe jede Stufe in 1–2 Sätzen mit Schlüsselbezug („… hängt von … ab").
HÜ (aus dem Semesterplan): „schlechte" Bestelltabelle normalisieren, jede Stufe begründen. Abgabe als Text + Tabellenliste (SQL optional).
