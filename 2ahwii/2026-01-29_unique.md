# unique

```sql
insert into person (1, "ERROR", 1);
insert into person values (1, "ERROR", 1);
CREATE UNIQUE INDEX person_id_index ON person(id);
select *from person a join person b on a.id = b.id;
select a.* from person a join person b on a.id = b.id;
select *from person a join person b on a.id = b.id;
select* from person a join person b on a.id = b.id and a.name is not b.name;
select * from person where name = 'ERROR';
delete from person where name = 'ERROR';
insert into person (name) values ('Neue unbekannte Person');
delete from person where name = 'Neue unbekannte Person';
CREATE UNIQUE INDEX person_id_index ON person(id);
insert into person values (1, "ERROR", 1);
```

Ein `CREATE UNIQUE INDEX` bewirkt in SQLite zwei Dinge gleichzeitig:

1. **Eindeutigkeit (Constraint):** Er stellt sicher, dass in den indizierten Spalten keine doppelten Werte vorkommen. Jeder Versuch, einen bereits vorhandenen Wert einzufügen, führt zu einem Fehler (SQLITE_CONSTRAINT).
2. **Performance (Index):** Er erstellt eine B-Baum-Struktur, die Suchabfragen (`SELECT ... WHERE spalte = x`) massiv beschleunigt.

**Syntax:**

```sql
CREATE UNIQUE INDEX idx_name ON table_name(column_name);
```

**Warum man es nutzt:**
Da SQLite – wie besprochen – kein `ALTER TABLE ADD CONSTRAINT` unterstützt, ist dies der einzige Weg, eine Spalte **nachträglich** als "unique" zu definieren, ohne die gesamte Tabelle neu zu erstellen.

**Wichtig:** Falls sich bereits Duplikate in der Spalte befinden, schlägt die Erstellung des Index fehl.
